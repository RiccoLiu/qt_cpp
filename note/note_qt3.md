# 性能优化

## 预渲染 & 离屏渲染

- 预渲染：复杂的数据计算和渲染放入QPixmap 做一个静态图, painEvent 中负责把静态图显示出来。 保证UI不卡顿
- 离屏渲染: 通常会将图像绘制在一个QImage，之后进行复杂的后处理特效或者给GPU提供一个单独的渲染目标。

使用场景：

- 预渲染 / 缓存背景： 使用 QPixmap 做静态背景图。
- 高频动态数据更新: 使用 QImage 图像存在内存中，使用 memcpy和 setPixel 写入效率极高，数据写入完成后使用QPixmap::fromImage()转换进行贴图

QPixmap 的局限：

由于 QPixmap 是存储在显存(VRAM)专为屏幕显示优化，如果频繁在 QPixmap 上进行绘制，会导致 CPU 和 GPU 之间发生大量的数据拷贝和同步，反而会成为性能瓶颈。

## 防闪烁 & 防撕裂

QWidget 默认双缓冲机制：

- 显卡永远只从前缓冲区(Front Buffer) 中读取数据并显示。
- 渲染引擎永远在后缓冲区(Back Buffer) 中把QPixmap拷贝进去。
- 显示器刷新时，一种方式将后缓冲区的数据拷贝到前缓冲区，会产生撕裂;另一种方式: 瞬间交换前后缓冲区(V-SYNC 硬件级别的同步显卡与操作系统)， 不会产生撕裂;

### 闪烁

paintEvent中画100个圆，屏幕刷新时会看到第1个圆、第2个圆... 依次显示，这样就形成了闪烁。双缓冲机制可以完美解决这个问题

常见的闪烁原因如下：

1. 设置了错误的属性，导致闪烁  
```
setAttribute(Qt::WA_PaintOnScreen, true);       // 直接在屏幕上绘制; 使用OpenGL场景需要设置，其他场景设置此属性必然导致闪烁;
setAttribute(Qt::WA_OpaquePaintEvent, true);    // 不要擦除背景; 如果当前 paintEvent 没有完全覆盖背景，没被覆盖的部分就会导致闪烁;
```

2. 多控件叠加与透明背景：透明背景的子控件覆盖在父控件之上时，由于父子控件独立绘制，绘制时间不同就会导致闪烁。  

3. 复杂视图控件： 像QTabview这种复合控件，每次刷新会逐项调用绘制函数，绘制前系统会优先进行背景擦除，当高频更新时也可能出现闪烁的现象

### 撕裂

当CPU往显存中写数据没写完，只写了一半，这时显示器的刷新信号到来导致这一帧有一半是上一帧的数据，一半是新的数据产生撕裂。

- 撕裂通常发生在高帧率 + 高刷新率的场景下.
- 撕裂的本质是在 CPU 拷贝过程中与显示器的刷新信号发生重叠导致；双缓冲机制并不能完全解决撕裂现象
- QWidget控件在高帧率和低帧率都会有撕裂现象，高帧率会更明显，低帧率不明显。
- QWdiget高帧率控件会严重消耗CPU资源, 如果控件超过60fps 建议使用 OPenGL 显卡显示。 
- 防撕裂的解决办法就是 OpenGL + 显示器同步 V-Sync
